# Safe Remediation

VoidGuard v0.2.0 поддерживает обезвреживание занятых файлов без универсального обхода системной защиты.

## Решения

| Статус | Значение |
|---|---|
| `QUARANTINED` | файл перемещён в закрытое хранилище |
| `LOCKED_BY_PROCESS` | Restart Manager обнаружил владельцев блокировки |
| `PROCESS_STOPPED` | остановлен точный процесс-цель |
| `DELETE_SCHEDULED` | удаление зарегистрировано на следующую загрузку |
| `REMOVED_VERIFIED` | после перезагрузки файл отсутствует |
| `STILL_PRESENT` | файл сохранился или был восстановлен |
| `BLOCKED_SYSTEM_POLICY` | цель запрещена системной политикой |
| `BLOCKED_PROCESS_POLICY` | процесс нельзя безопасно завершить |

## Когда можно остановить процесс

Остановка разрешена только для процесса, чей executable path точно совпадает с canonical path выбранного файла. VoidGuard блокирует системные PID, критические имена Windows, Microsoft-signed и защищённые executable.

Для DLL, скрипта или файла данных совпадения executable path обычно не будет. В этом случае завершать процессы нельзя — используйте scheduled deletion.

## Scheduled deletion

Операция требует администратора и точной строки подтверждения. VoidGuard:

1. повторно проверяет системную policy;
2. вычисляет SHA-256;
3. вызывает `MoveFileEx(..., MOVEFILE_DELAY_UNTIL_REBOOT)`;
4. сохраняет JSON-запись в pending ledger;
5. после перезагрузки проверяет существование пути.

Если статус стал `STILL_PRESENT`, объект мог быть восстановлен службой, задачей, WMI subscription или другим компонентом. Проверьте `PERSISTENCE MATRIX` и выполните Microsoft Defender Offline.

## Что VoidGuard намеренно не делает

- не завершает произвольный PID;
- не отключает PPL;
- не выгружает драйверы ядра;
- не обходит TrustedInstaller/WRP;
- не удаляет каталоги и корни дисков;
- не обещает удалить rootkit из работающей Windows.
